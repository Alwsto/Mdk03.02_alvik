Дефекты и результаты проверки — GuestPass Manager, вариант 5

GP-01 / Critical / учебный антипример / закрыт в безопасном API
IDOR: GET по чужому id возвращает объект без проверки владельца.
Причина: запрос к EF Core проверяет только Id; аутентификация отсутствует.
Исправление: PassRead + непустой sub + PassAccess.CanRead (owner или Guard).
Подтверждение: I02_IdorReturns403AndRecordsDenied, I03_GuardReadsOtherPass,
I04_AnonymousRequest401IsAudited, I13_RealBearerValidation.

GP-02 / Major / учебный антипример / закрыт в безопасном API
Нет аудита чтения, отказов и анонимных попыток; действия нельзя расследовать.
Исправление: AuditMiddleware, AuditEvents, HMAC actor, статус/исход/TraceId,
транзакция бизнес-операция+аудит, аварийный ответ503 с откатом.
Подтверждение: I01, I02, I04, I09, I10, I15.

GP-03 / Major / дополнительное усиление / закрыт в безопасном API
В антипримере нет ограничения частоты запросов; перебор id не ограничен.
Исправление: rate limiting 60 запросов/мин на sub, для анонимных — на IP.
Подтверждение: I09_RateLimit429IsAudited, I15_AnonymousRateLimitAndAudit.
Это не замена внешней DDoS-защите: отказ429 также требует записи аудита.

GP-04 / Major / реально найден при первом запуске тестов / исправлен
Условие: Windows без прав записи в системный EventLog, имитация отказа аудита.
Ожидание: общий503 и откат создания. Факт первого запуска: LogCritical
выбросил AggregateException/AccessDenied вместо корректного ответа503.
Причина: добавление JsonConsole не удаляло стандартный провайдер EventLog.
Исправление: builder.Logging.ClearProviders().AddJsonConsole().
Повтор: I10_AuditFailure503RollsBackCreation прошел; весь набор39/39.
Доказательства: evidence/GuestPass.Tests.initial.trx, test-output-initial.txt
и итоговые GuestPass.Tests.trx, test-output.txt.

Дополнительные меры, которые не следует выдавать за найденные SQL-инъекции:
LINQ-запросы EF Core параметризованы; антипример также использует LINQ.
SQLi в приведенном антипримере не обнаружена. I12 доказывает, что строка,
похожая на SQL, сохраняется как обычное значение и не удаляет таблицу.
DTO исключает присваивание OwnerId/Role; I11 проверяет отсутствие повышения прав.
JWT проверяет подпись, алгоритм HS256, issuer, audience, exp и непустой sub.
Ключи не зашиты в код; неверные/короткие/отсутствующие ключи отвергаются.
